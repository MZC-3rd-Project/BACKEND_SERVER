# MSA Inner - 핫딜 대기열과 원자적 재고 차감

핫딜 내부 설계에서 대기열은 단순한 줄 세우기 기능이 아니라, 순간적으로 몰리는 구매 요청을 한 번에 재고 차감 로직으로 흘려보내지 않기 위한 트래픽 제어 장치다. 사용자가 대기열에 진입하면 HotDeal 서비스는 Redis ZSet에 순번을 저장하고, 재진입 시에도 기존 순번을 유지하도록 멱등적으로 처리한다. 이후 스케줄러가 활성 핫딜의 남은 재고와 현재 동시 처리 가능 수를 기준으로 입장 허용 대상을 계산하고, 허용된 사용자만 실제 체크아웃 예약 단계로 진입할 수 있게 제어한다. 이 구조를 통해 모든 요청이 동시에 구매 로직으로 몰리는 상황을 줄이고, 재고 경쟁이 가장 심한 구간을 한 번 걸러낼 수 있다.

하지만 대기열만으로는 재고 정합성을 완전히 보장할 수 없다. 그래서 실제 체크아웃 예약 시점에서는 Redis Lua Script를 사용해 핵심 검증과 재고 차감을 하나의 원자적 연산으로 묶었다. 이 스크립트는 현재 재고 확인, 1인당 구매 제한 확인, 기존 예약 존재 여부 확인, 재고 차감, 예약 저장을 한 번에 처리한다. 즉 여러 사용자가 거의 동시에 예약을 시도하더라도 중간에 재고 값이 엇갈리거나, 검증과 차감 사이에 틈이 생겨 과판매로 이어지는 문제를 줄일 수 있다. 발표에서는 이 부분을 "대기열로 유입을 제어하고, Lua Script로 최종 재고 차감을 원자적으로 보장했다"라고 정리하면 된다.

이 흐름은 두 단계로 설명하면 가장 이해가 쉽다. 1단계는 Redis 기반 대기열과 admission control을 통한 트래픽 분산이다. 여기서는 사용자를 순서대로 관리하고, 실제 구매 처리 구간에 동시에 들어오는 인원을 제한한다. 2단계는 체크아웃 예약 시점의 Lua Script 실행이다. 여기서는 이미 허용된 사용자만 대상으로 재고와 구매 제한을 다시 검증한 뒤, 재고 감소와 예약 저장을 한 번에 처리한다. 즉 1단계가 유입 제어라면, 2단계는 동시성 상황에서도 재고 정합성을 지키는 최종 안전장치다.

또한 예약이 취소되거나 만료되는 경우에는 보상 로직을 통해 재고를 다시 복구하도록 설계했다. 이 점을 함께 설명하면 단순히 빠르게 판매하는 구조가 아니라, 예약 실패나 중간 이탈까지 고려한 복구 가능한 설계라는 점을 보여줄 수 있다. 따라서 Inner 설계의 핵심은 대기열 자체보다도, 대기열과 원자적 재고 차감을 결합해 과도한 동시 요청과 과판매 위험을 함께 제어했다는 데 있다.

## 핵심 키워드

- Redis ZSet 대기열
- Admission Control
- 동시 구매 요청 분산
- Redis Lua Script
- 원자적 재고 차감
- 1인당 구매 제한
- 중복 예약 방지
- 과판매 방지
- 예약 취소/만료 시 재고 복구

## 슬라이드에 넣을 자료

- 사용자 -> HotDeal Service -> Redis Queue -> Scheduler -> Checkout Reserve 흐름의 시퀀스 다이어그램
- Redis 자료 구조 요약
- `queue`: ZSet
- `admitted`: Key
- `token`: Key
- `reservation`: TTL 기반 Key
- `stock`: Value
- Lua Script 결과값 요약
- `1`: 예약 성공
- `0`: 재고 부족
- `-2`: 1인당 구매 제한 초과
- `-3`: 이미 예약 존재

## 발표용 정리 문장

핫딜 내부에서는 먼저 Redis 기반 대기열로 순간적인 구매 요청을 제어하고, 허용된 사용자만 체크아웃 예약 단계로 넘깁니다. 하지만 대기열만으로는 재고 정합성이 완전히 보장되지 않기 때문에, 실제 예약 시점에서는 Redis Lua Script를 사용해 재고 확인, 구매 제한 검증, 중복 예약 확인, 재고 차감, 예약 저장을 하나의 원자적 연산으로 처리했습니다. 즉, 대기열은 유입을 조절하는 역할이고, Lua Script는 동시성 상황에서 과판매를 막는 최종 안전장치 역할을 합니다.
